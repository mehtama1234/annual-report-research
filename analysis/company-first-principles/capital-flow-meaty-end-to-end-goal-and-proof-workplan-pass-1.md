# Capital Flow Meaty End-To-End Goal And Proof Workplan Pass 1

## Purpose

This page consolidates the big-picture goal for the capital-flow project after the big-money-player map, named-cash proof ladder, and Apollo/Athene statutory work.

The practical question is:

`Who is investing where, where does the money come from, how does it move, what does it go into, and what cash comes back?`

The structured companion table is:

`analysis/company-first-principles/data/capital-flow-meaty-end-to-end-goal-and-proof-workplan-pass-1.csv`

## Meaty End-To-End Goal

`Build a document-backed money-movement map for the largest capital routers, then prove selected named cash loops from original source pool to platform, legal wrapper, instrument, named borrower/project/asset, use of proceeds, operating cash or settlement, legal payback route, and return evidence.`

In simple words:

`Show who has the money, who routes it, where it lands, what it funds, whether cash comes back, and which documents prove the links.`

## North Star Deliverable

The end product should be a ranked, evidence-backed money-flow atlas.

It should let a reader open one table and answer:

1. `BlackRock, Blackstone, Apollo/Athene, KKR/Global Atlantic, Brookfield, Ares, or Carlyle controls/routes what pool of money?`
2. `That money moves through which wrapper: insurer balance sheet, fund, BDC, ETF, credit facility, ABS/ABF structure, infrastructure vehicle, utility recovery mechanism, or public debt?`
3. `The money lands in which named borrower, company, project, asset, collateral pool, or operating lane?`
4. `The money is used for what: acquisition, capex, refinancing, working capital, fleet, collateral advance, project buildout, energy infrastructure, utility spend, or private-company funding?`
5. `What cash comes back: customer receipts, interest, principal, settlement, investment income, tariff revenue, billing recovery, asset sale, maturity proceeds, or operating cash flow?`
6. `What legal route controls that cash: debt waterfall, statutory schedule, trust report, collateral certificate, borrowing base, rate order, covenant package, or legal-entity distribution path?`
7. `What return can be measured: spread, yield, IRR, ROIC, payback, DSCR, cash-on-cash, gain/loss, or NPV?`

The atlas should not blur map evidence with proof evidence. Each row must say whether it is only a `map`, a `bridge`, a `named-cash-hold`, or `full-proof`.

## What Done Means

This project is done only when the system can produce two outputs at the same time:

1. **Big-money answer:** a platform-level map showing who is investing where across the major capital routers.
2. **Named-cash answer:** a smaller set of proof packets that follow selected examples all the way from money source to cash return or clearly show where public evidence stops.

For a row to become `full-proof`, it must connect all of these without guesswork:

`source pool -> platform -> legal wrapper -> instrument -> named destination -> use -> cash-back evidence -> legal/waterfall availability -> return evidence`

If the row cannot connect all nine pieces, the conclusion must say exactly what is missing.

## What We Are Not Doing

This is not a project to collect impressive AUM numbers.

This is not a project to say private credit, infrastructure, insurance capital, or AI/data-center capex is important in general.

This is not a project to infer cash movement from press releases alone.

The job is to prove actual money paths with receipts, billing records, debt waterfalls, legal-entity schedules, collateral certificates, statutory filings, borrower documents, trustee reports, and return models where available.

This is not a generic private-credit, infrastructure, insurance, or AI-capex theme project. The goal is a proof system that can say:

1. `This platform controls or routes this kind of money.`
2. `This wrapper carries the money.`
3. `This named company, borrower, project, collateral pool, or asset receives it.`
4. `This is what the money appears to fund.`
5. `This is the cash, receipt, income, sale, maturity, billing, or repayment evidence that comes back.`
6. `This is the legal or financial document family that proves or fails to prove the full chain.`

## Core Money Chain

The required chain is:

`capital source -> big-money platform -> legal wrapper -> instrument -> named destination -> use of proceeds -> operating output or asset ownership -> receipt, settlement, investment income, billing, or repayment -> waterfall/legal availability -> return model`

If a case cannot walk this chain, it can still be useful, but it must be labeled correctly:

| Level | Meaning |
|---|---|
| `map` | We know the platform, wrapper, lane, or destination category. |
| `bridge` | We have a named borrower, asset, project, holding, source/use, cash proxy, or legal schedule, but not the complete cash loop. |
| `named-cash-hold` | We have strong named evidence, but one decisive proof document is missing. |
| `full-proof` | Source, wrapper, destination, use, cash-back evidence, legal payback route, and return evidence all connect. |

Most current work is at `map`, `bridge`, or `named-cash-hold`. That is useful, but it is not final proof.

## What We Need To Answer The User's Questions

To answer `who is investing where`, each platform needs a destination table:

`platform -> wrapper -> lane -> named borrower/project/asset -> amount -> period -> source document`

To answer `where does the money come from`, each row needs a source stack:

`retirement liability, insurance reserve, ETF holder, institution, wealth client, public debt buyer, bank facility, BDC shareholder, CLO noteholder, operating cash, or utility customer`

To answer `how does it move`, each row needs a wrapper/instrument:

`statutory account, private-credit fund, BDC, revolver, ABL, term loan, note, preferred, stream, tariff, rate-recovery clause, project-finance vehicle, securitization, or acquisition financing`

To answer `into what`, each row needs a named destination and use:

`borrower, portfolio company, legal entity, project, plant, fleet, collateral pool, backlog, acquisition, refinancing, working capital, capex, construction, stream, or regulated program`

To answer `what cash comes back`, each row needs one or more hard cash documents:

| Cash Question | Decisive Documents |
|---|---|
| Did customers pay? | receipts, billing determinants, invoice collections, tariff billing, rate-clause actuals, customer settlement reports |
| Did the borrower pay? | interest/principal schedules, borrower financials, lender statements, amortization table, payoff letter |
| Did the asset generate cash? | project EBITDA/DCF, asset-level revenue, toll/tariff/contract revenue, DSCR reports, trustee account statements |
| Did the insurer earn spread? | statutory investment income, asset schedule, liability reserve/cost, IMR/AVR, credit quality, sale/maturity proceeds |
| Did collateral support borrowing? | borrowing-base certificate, collateral certificate, eligible collateral, advance rate, reserves, NOLV, L/C schedule |
| Did the transaction settle? | funds-flow memo, closing statement, paying-agent record, trustee report, redemption notice, use-of-proceeds table |
| Was there a return? | IRR, NPV, ROIC, payback, cash-on-cash, realized gain/loss, fair-value marks, impairment/non-accrual evidence |

## End-To-End Workplan

### Phase 1: Build The Platform-To-Destination Spine

Create one row per big platform and one row per best named proof chase.

Required output:

`platform -> money source -> wrapper -> destination lane -> named chase -> known evidence -> missing proof`

Current status: started through the big-money-player map and platform proof chase matrix.

### Phase 2: Pick One Prototype That Can Actually Reach Cash

Apollo/Athene is the prototype because the statutory filing exposes more of the chain than a normal public-company 10-K.

Required output:

`Athene legal entity -> liabilities/source context -> Schedule D/BA assets -> income -> sales/maturities/repayments -> named issuer/proceeds rows -> cash-return hold/pass verdict`

Current status: materially advanced. We now have Schedule D holdings, income/cash bridge, and disposal/proceeds parser output. The next move is CUSIP-level matching and reconciliation.

### Phase 3: Build One Comparable Case In Private Credit

Ares/Frontline is the first private-credit borrower proof chase.

Required output:

`Ares-linked vehicle/holder -> borrower facility -> use of proceeds -> borrower cash flow -> lender allocation -> repayment or bank-role outcome`

Current status: named borrower and holder/arranger evidence exist, but facility documents and cash waterfall are missing.

### Phase 4: Build One Operating-Asset Cash Case

Choose one among FPL, URI, Wheaton/Antamina, Cheniere, or Energy Transfer.

Required output:

`source/use -> asset/project/collateral/program -> operating output -> customer/settlement cash -> waterfall/legal route -> return model`

Current status: several cases are strong bridges, but none has every receipt/waterfall/return document.

### Phase 5: Convert The Findings Into A Claim Register

Every promoted claim should be assigned:

1. safe sentence
2. proof level
3. decisive evidence
4. missing document
5. forbidden overclaim

The final product is not a pile of notes. It is a ranked claim register that separates what is proven from what is only suggested.
