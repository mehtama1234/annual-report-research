## How to use this roster

- claim the company here if its main value is to sharpen one of the blind-spot systems
- leave the company to the ordinary sector thread if its value is mostly standard industry coverage
- prefer synthesis work when a lane already has enough anchors
- screen the name first with the short ownership rule before using this roster as a claim list
- route the company through the consumer-behavior core or infrastructure core first before deciding on a narrower lane

Do not treat a thin, stale, awkward, or incomplete `AnnualReports` industry page as a claim reason by itself.

## First routing question

Use the consumer-behavior core first for:

- `comfort`
- `value`
- `routine`
- `ritual`
- `identity`
- `participation`

Use the infrastructure core first for:

- `control`
- `access`
- `workflow`

## Usually leave to the ordinary sector threads

Unless they materially improve one of the blind-spot lanes above, this thread should usually not claim:

- ordinary upstream materials producers
- standard machinery and industrial backlog names
- conventional utilities
- generic regional banks and plain insurers
- straightforward pharma, medtech, and hospital names
- generic software issuers with no ecosystem, participation, wallet, or interface-control angle
- generic hardware, telecom, or industrial issuers with no hidden-infrastructure, access-layer, or workflow-control angle
- ordinary consumer brands whose only contribution is more category backfill

## Collision rule

If a company could fit both a normal sector thread and this thread, this thread should keep it only when the blind-spot explanation is clearly stronger than the formal industry explanation.

If that is not true, let the normal sector thread keep it.

Thin browse-tree page quality alone does not make the blind-spot explanation stronger.

## Best immediate use

Use this as the default take-versus-leave roster when assigning work across threads so this blind-spot lane stays focused on what `AnnualReports` does not organize well.

Route through the two top-level cores first, then use this roster to choose the narrower lane.

If the narrower lane is one of the mature infrastructure lanes, then use the matching extension shortlist before taking another name.
