## One-sentence rule

If `AnnualReports` already gives a company a clean industry home, leave it to the normal sector thread.

Take it here only when the real value comes from a system the browse tree does not express well.

This is a structural-taxonomy lane, not an uncovered-sector cleanup lane.

Thin or awkward page quality by itself is not a reason to hunt the company here.

Use the short [AnnualReports Noncovered Ownership Rule](/home/manishmehta/ui-projects/annual-report-research/indexes/annualreports-noncovered-ownership-rule-2026-08-10.md) first when a worker needs a one-screen keep-versus-leave decision before reading the longer collision-control files.

## The two top-level routes

Screen the name with the short ownership rule, then route the candidate through one of these two cores:

- `Consumer behavior`: `comfort`, `value`, `routine`, `ritual`, `identity`, `participation`
- `Infrastructure`: `control`, `access`, `workflow`

If it does not fit either route cleanly, the default is skepticism.

## This thread should actively own

The cleanest one-screen ownership statement is now:

- behind-the-shelf consumer infrastructure
- hidden connectivity and access-layer ownership
- control-layer and connectivity infrastructure
- physical execution and embedded workflow systems

Everything else in the blind-spot lane should usually be conditional:

- consumer behavior and cultural-demand systems
- relationship ownership, wallet, and coordination systems
- cross-sector built-environment systems

### Immediate ownership order when other threads cover the normal browse tree

If ordinary `AnnualReports` industries are already being handled elsewhere, this thread should prioritize the residual systems in this order:

1. hidden consumer infrastructure behind visible demand
2. control-layer and connectivity governance
3. hidden connectivity and access-layer ownership
4. physical execution and embedded workflow control
5. everything else only when the subtype gain is real rather than just another packet

This order is strict on purpose.

The top of the list is where the `AnnualReports` browse tree is weakest and where ordinary sector packetization is least likely to produce a coherent system read on its own.

## Fast practical answer

If another worker asks what this thread should cover because the other threads are already covering the ordinary `AnnualReports` sectors, the shortest correct answer is:

- hidden infrastructure behind visible demand
- control and access layers that sit underneath connectivity and bandwidth dependence
- workflow-control businesses that look industrial in the source taxonomy but behave like embedded operating systems
- marketplace, wallet, membership, recurring-attention, and built-environment systems only when the business model or system split is stronger than the formal industry label
- consumer and cultural systems only when they sharpen a live boundary instead of just adding another category example

## Usually leave to the other threads

- ordinary commodity and upstream materials names
- plain industrial backlog and machinery names
- generic utilities
- generic banks and insurers with no stronger wallet or relationship-system angle
- straightforward pharma, medtech, and hospital packetization
- ordinary software, hardware, or telecom names with no stronger ecosystem, control-layer, access-layer, or workflow-control explanation
- ordinary consumer brands whose only contribution is category breadth

## Fast collision rule

Keep the company here only if removing it would make a blind-spot memo, system index, or comparison set weaker.

If removing it would not weaken the blind-spot layer, leave it to the normal sector thread.
