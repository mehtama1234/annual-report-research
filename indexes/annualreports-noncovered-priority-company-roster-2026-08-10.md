## How to read this roster

- `Take now`: highest-fit names or clusters for this thread because the system explanation is clearly stronger than the ordinary industry explanation
- `Take only if subtype gain is real`: valid blind-spot names, but only if they add a materially different subtype, boundary, or comparison quality
- `Leave to normal threads`: names that should usually remain with ordinary sector coverage unless a very specific blind-spot angle emerges
- screen names first with the short ownership rule before using this roster for priority selection
- route names through the consumer-behavior core or infrastructure core first before deciding which bucket they belong in

Do not use this roster as a reason to claim a company just because its live `AnnualReports` industry page looks thin, awkward, stale, or incomplete.

## First routing question

Use the consumer-behavior core first for names that feel strongest as:

- `comfort`

- `routine`
- `ritual`
- `identity`
- `participation`

Use the infrastructure core first for names that feel strongest as:

- `control`
- `access`
- `workflow`

## Leave to normal threads

These should usually stay out of this blind-spot lane unless a very specific system-level argument becomes stronger than the industry label.

| Company type | Why this thread should usually leave it |
|---|---|
| ordinary commodity, mining, chemical, and upstream materials names | the formal industry label is usually already the main explanation |
| plain industrial backlog and machinery names | backlog, end-market, and manufacturing exposure usually explain them well enough |
| generic utilities | the blind-spot layer gains little unless there is a stronger wallet, access, or civic-flow system angle |
| ordinary regional banks and plain insurers | these usually belong to normal financial coverage unless wallet, loyalty, or status mechanics dominate |
| straightforward pharma, medtech, and hospital names | normal healthcare packetization usually captures the main story |
| ordinary software or hardware names with no stronger ecosystem, attention, infrastructure, or workflow-control logic | these are better handled by normal sector coverage |
| ordinary consumer brands that only add category breadth | this thread should not become residual brand backfill |

## Fast operating rule

Take the company only if removing it from this thread would make a blind-spot memo, comparison, or system index weaker.

If removing it would not weaken the blind-spot layer, leave it to the normal sector thread.

Thin browse-tree page quality by itself is not a reason to override that rule.

If the company falls inside one of the mature infrastructure lanes, use the matching extension shortlist before treating it as the next blind-spot move.
