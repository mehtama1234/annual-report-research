## The default answer

The default answer is `leave`.

This thread should claim a company only when the system-level explanation is clearly stronger than the ordinary industry explanation.

If that is not clearly true, leave the company to the normal sector thread.

Use the short [AnnualReports Noncovered Ownership Rule](/indexes/annualreports-noncovered-ownership-rule-2026-08-10.md) first when a worker needs a fast screen before running the full protocol.

## Four-step protocol

### Step 1: identify the formal `AnnualReports` home

Write down the company's visible site label first:

- sector
- industry
- the obvious normal-thread destination

Do not treat a thin, stale, or sparse industry page as a blind-spot claim by itself.

If that label already describes the company well enough for the archive's purpose, stop and leave it.

### Step 2: ask the real operating-system question

Ask:

"is the company's real value mainly explained by a system that cuts across the `AnnualReports` tree?"

That means asking whether the company is better understood through:

- relationship ownership
- marketplace or coordination logic
- attention capture
- membership, loyalty, or wallet control
- recurring behavior
- hidden infrastructure
- access-layer ownership
- workflow control
- cross-sector built-environment dependence

If the answer is no, leave it.

### Step 3: require a concrete blind-spot gain

Keep the company only if it does at least one of these:

1. completes or sharpens an existing blind-spot lane
2. adds a genuinely different subtype inside an existing blind-spot lane
3. supports a direct boundary comparison that would otherwise be weak
4. exposes a structural behavior, cultural, industrial, or infrastructure pattern that the formal industry label hides

If none of those are true, leave it.

If the company lands inside one of the mature infrastructure lanes, run the matching extension shortlist before treating it as the next blind-spot move.

### Step 4: run the strict tie-breaker

If the company still looks debatable, use this tie-breaker:

- keep it here only if removing it would weaken a live blind-spot memo, index, or comparison
- otherwise leave it to the normal sector thread

Ambiguous names should not be absorbed by this thread just because they are interesting.

## Hard keep rules

Keep the company in this thread if any of these are clearly true:

1. the `AnnualReports` label is materially misleading compared with the operating reality
2. the company is mainly useful as part of a cross-sector system already defined in the blind-spot index
3. the company belongs in an already anchored comparison set where the comparison logic is more valuable than the sector packet
4. the company is economically driven by control of interface, attention, loyalty, participation, infrastructure, access, or workflow rather than by a standard product-category description

## Hard leave rules

Leave the company to another thread if all of these are true:

1. the formal `AnnualReports` category is a good-enough description
2. the company mostly adds ordinary sector coverage
3. the company does not sharpen an active blind-spot lane
4. the company can be removed from this thread without weakening a comparison, system memo, or priority map
5. the best argument for keeping it is only that the browse-tree industry page looks thin, stale, or incomplete

## The lanes this protocol is meant to protect

This thread should mainly own, by default first-claim priority:

- hidden consumer infrastructure
- control-layer and connectivity infrastructure
- hidden connectivity and access-layer ownership
- physical execution and embedded-workflow systems

The following lanes remain valid blind-spot work, but they should usually be conditional rather than default first-claim work:

- retail as a system
- marketplace and coordination systems
- recurring attention and cultural-distribution systems
- relationship ownership and channel control
- loyalty, wallet, membership, and status systems
- consumer behavior and cultural-demand systems
- modern built-environment systems

This thread should usually not own:

- ordinary commodity or materials coverage
- plain industrial backlog coverage
- generic utilities
- generic bank and insurer coverage
- straightforward healthcare packetization
- ordinary software, hardware, telecom, or media packetization with no stronger system explanation
- routine consumer-brand backfill with no stronger behavior or relationship logic

## Simple examples

`Keep here` examples:

- `Cloudflare`: better explained as edge trust and application-control infrastructure than as a plain internet or software name
- `American Tower`: better explained as scarce access-layer ownership than as generic real estate
- `United Rentals`: better explained as access-over-ownership workflow control than as ordinary rental coverage
- `Costco`: often more useful as a membership and relationship-thickness system than as ordinary retail

`Leave there` examples:

- a standard chemical producer that mainly adds more materials coverage
- a routine regional bank with no stronger wallet, status, or membership-system angle
- a plain industrial manufacturer whose main story is backlog and end-market exposure
- a conventional consumer brand whose only value is more category backfill

## One-line command

If the company strengthens a system that `AnnualReports` classifies badly, keep it.

If it mainly strengthens a normal sector page, leave it.
