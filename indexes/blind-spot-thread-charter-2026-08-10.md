## Core rule

If a company is mainly useful because it fills a normal sector gap, another thread should own it.

This thread should claim work only when the main analytical value comes from something the source taxonomy does not express well.

Operational version:

- think in systems first and company packets second
- weak page quality alone is not a reason to claim a company
- if the browse tree already explains the company well enough, this thread should not own it

## What this thread owns

### 1. Cross-sector pattern mapping

- retail system types
- DTC versus channel control
- marketplace and ecosystem control
- loyalty, wallet, and membership systems
- relationship-thickness systems
- modern real-estate and infrastructure crosswalks
- hidden infrastructure beneath visible consumer or software layers

### 2. Consumer, cultural, and societal behavior layers

- comfort and casualization
- value-hunt and bargain discovery
- routine-use trust and replenishment
- beauty, fit, and self-presentation
- ritual, occasion, and stimulation
- fandom, play, and participation
- recurring attention and cultural-distribution

### 3. Business-model overlays

- marketplace versus owned inventory
- direct relationship ownership versus channel dependence
- advertising, seller-services, loyalty, or licensing as second monetization layers
- thick versus thin relationship monetization

### 4. Taxonomy-breaker cases

Own the cases where the source taxonomy hides the real operating system.

Examples already visible in the archive:

- `Airbnb`
- `eBay`
- `Birkenstock`
- `Kenvue`
- `Carnival`

### 5. Default first-claim areas

The strongest default first-claim areas are:

- behind-the-shelf consumer infrastructure
- control-layer and connectivity infrastructure
- hidden connectivity and access-layer ownership
- physical execution and embedded workflow systems

## What this thread should avoid

- plain sector backfill with no cross-sector angle
- near-duplicates of already-covered patterns
- packet work whose only value is ordinary industry coverage
- generic industrial, telecom, or hardware names whose best explanation is still their formal category

## Company-selection test

This thread should normally take a company only if at least one of these is true:

1. It strengthens a cross-sector memo the normal taxonomy cannot produce cleanly.
2. It adds or sharpens a missing behavior lane.
3. It clarifies a business-model distinction.
4. It is a taxonomy-breaker whose source bucket is materially weaker than its operating reality.

If none of those are true, another thread should usually own the company.
