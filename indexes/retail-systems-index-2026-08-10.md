The goal is to make the retail correction layer sortable by:

- retail subtype
- subtype family
- source-taxonomy sector and industry
- relationship type
- repeat behavior
- frequency band
- physical embedding
- second monetization layer
- price or identity axis
- discretionary intensity
- primary monetization side

## Highest-confidence uses

- sort retail names by relationship type instead of by the legacy source sector
- sort the lane by subtype family, frequency band, and discretionary intensity
- separate paid utility membership, replenishment-and-basket-data retail, and treasure-hunt discovery on one page
- separate bargain-discovery, replenishment, utility, brand-control, beauty, and project retail systems
- compare which retail models have the thickest second monetization layer
- keep track of where retail is really a marketplace, a service layer, or a workflow system
- separate buyer-membership, buyer-brand, buyer-traffic, seller-and-ad, and service-weighted monetization patterns

## Current best next moves

1. Reuse the direct `Costco` versus `Kroger` versus `TJX` comparison first when the question is whether a retailer belongs closer to paid utility membership, replenishment-and-basket-data retail, or treasure-hunt discovery.
2. Use the now-covered `Home Depot` versus `Lowe's` pair to tighten project-retail and pro-workflow comparison before adding another home-improvement anchor.
3. Add a narrower hierarchy file later only if the utility, brand-led, and project-retail subtypes become crowded enough to need a second dedicated retail-family screen.
4. Reuse the same pattern for a DTC-only or bargain-discovery-only index if the retail blind-spot lane keeps expanding.
